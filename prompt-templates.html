The shared spine

All six families are built from the same eight parts, in the same order. Only the length and the packaging change. A 532-character arcade prompt and a 12,527-character flagship prompt do the same eight jobs; the short one just does several of them in a single clause.

The prompt opens with an intent line that starts with a verb and names the subject, the scale, the light and the moment. A negative list follows in 26 of the 63 prompts: four cheap answers, named and forbidden. Then comes the goal and the means together, which is an impossible density paired at once with the technique that pays for it. After that the technical boilerplate is pasted in unchanged.

The body then describes the first frame, which is what fills the screen before anyone touches anything. It builds the world and its life, naming real landmarks and four or five things that move independently. It lists the controls: a set of camera presets, three sliders, a photo mode and a reset. It closes on performance, which states the detail tiers, the order in which quality may be sacrificed, the laptop target, and one final sentence naming the payoff.

The central trick: never ask for one without the other

The writer of this collection never asks for a spectacular result without naming, in the same breath, the engineering that makes it affordable. Density is always paired with instancing. Fine detail is always paired with level of detail. Ambition is always paired with a laptop frame rate. A control is always paired with a visible consequence.

This pairing removes an escape route. A model that is told only "make it dense" can either draw a hundred objects and call it dense, or draw a million and freeze the browser. Told both halves at once, it has to find the third answer, which is the correct one.

The degrade order, the sharpest device in the collection

Every renderer eventually has to give something up to keep running. Left to itself, a model gives up whatever is easiest to remove, which is usually the thing the prompt was really about. The collection prevents this by naming the sacrifice order explicitly. Prompt 1 puts it like this:

"Quality selector degrades far window variation, traffic density and reflections before ever degrading island completeness or landmark silhouettes."

The clause tells the model what the scene is for. Cheap things may go. The graded things may not. 33 of the 63 prompts contain a version of this instruction. If you write only one sentence from this whole document into your own prompt, write this one.

Every prompt, opened up

Click a title to open it. The strip repeats the eight parts for that prompt. The prompt is then cut into sections and each section is headed with the part it is doing, so the shape of the prompt can be read down the page against the wording that fills it. Within the text, dimmed wording appears in at least one other prompt as well; everything at full contrast is unique to this one.

The sections are Peter's own. The cut falls where he put a markdown heading, which 51 of the 63 prompts use, and at a blank line everywhere else. Nothing is reordered or reworded: each section runs exactly as it does in prompts.json. Where a section carries a heading, the heading names the part, which is itself worth learning: Performance discipline is part h and Exploration and controls is part g, whatever the sentences underneath happen to mention. Where there is no heading, the part that owns the most characters in the section wins it. That gives 436 sections across the collection, 6.9 per prompt.

A second, quieter label appears where one section is plainly doing two jobs: the part holds at least a quarter of the section, or it is part b. The negative list is short and always sits inside a longer opening paragraph, so it never wins a section on length, yet it is one of the moves most worth seeing; it is shown wherever it occurs. The opening section is part a by definition, because that is where a prompt names its subject, and what else it carries is shown beside it.

The strip and the section headings measure two different things and will not always agree. The strip asks whether a part appears anywhere in the prompt; the headings ask which part dominates each section. A part can be present and dominate no section, so a letter can sit in the strip and never appear down the page. The reverse never happens: every letter in the page is also in the strip, and a build assertion enforces it. One consequence worth naming: the spine is ordered on average — the median position of each part through the text runs a, b, d, e, c, f, g, h — but only 19 of the 63 prompts run cleanly from a to h without revisiting a part. Peter comes back to detail after controls, and puts life back in after performance.

How to write a new prompt

Work through these steps in order. Steps 1 to 3 are decisions. Steps 4 to 21 are writing. Step 22 is the check.

  1. Pick one subject and one exact moment. Name the light.
  2. Write the hook in one line. Example: "a forest wearing a million butterflies".
  3. Choose the family by target length. Use the table in section 4.
  4. Write the intent sentence. Start with the verb "Create" or "Build".
  5. List four cheap answers a model would give. Use the negative-list table.
  6. Write the negative clause: "This must not be A, B, C, or D."
  7. State the impossible density. Name the unit: pieces, brushstrokes, wings, blocks.
  8. Name the technique that pays for it. Forbid the lazy alternative in the same sentence.
  9. Paste the import-map block. Choose the standard or the strict wording.
  10. Write the first frame. Describe only what fills the screen at second zero.
  11. Add the no-front-end clause. Use block 4.
  12. Name the hero mechanic in its own header. Name the failure it must avoid.
  13. List six to ten real landmarks or features by name. Give true proportions.
  14. Write four or five independent moving systems. Give each one its own bullet.
  15. State the default light. Name four to six material classes.
  16. Write four to seven camera presets. Separate them with semicolons.
  17. Write "Compact controls only:" then three controls and photo mode.
  18. Write the performance tiers: far, mid, near, impostor.
  19. Write the degrade order. Name what may drop and what may never drop.
  20. Close with "Smooth on a modern laptop, devicePixelRatio clamped to 2."
  21. Write the outcome sentence. Name the feeling, not the feature.
  22. Count the characters. Compare against the family range. Cut or expand.

Warning: do not skip step 19. Without a degrade order, a model cuts the graded feature first to reach the frame rate.

Pre-flight checklist

Check a finished prompt against these 14 items. The source collection satisfies all of them.

  • The first sentence names the subject, the scale and the moment.
  • Four cheap shortcuts are named and forbidden.
  • The density target is stated, with a unit.
  • The technique that delivers the density is named, and the lazy one is forbidden.
  • The import-map block is present, word for word.
  • "Everything procedural; no external assets" is present.
  • The first frame is described. No menu, no title, no loading state.
  • At least six landmarks or features are named individually.
  • Four or five independent moving systems each have their own bullet.
  • The palette is named. For family B, hex codes are given.
  • Four to seven camera presets are listed.
  • Controls number three, plus photo mode. No more.
  • The degrade order names what drops and what never drops.
  • The closing line gives the laptop target and one outcome sentence.

Who these prompts are written for

These are not prompts for a person. They are test prompts for a coding model, and two of them say so in plain words. Prompt 16 and prompt 18 both contain this sentence:

"The output should feel like a flagship benchmark scene for a frontier web agent."

Read that way, everything else falls into place. Each prompt asks for one web page that works on its own. 62 of the 63 name Three.js, the standard 3D library for browsers. 48 demand procedural generation, which means the code itself must build every shape, colour and texture. 33 state outright that no external files may be loaded. The model gets no pictures and no ready-made 3D models. It writes all of it.

Somebody then opens that page, looks at the first thing on screen, moves the mouse, and forms a judgement. That single fact explains every pattern in this document. The prompts are not written to describe a scene. They are written to block the shortcuts a model would otherwise take.
